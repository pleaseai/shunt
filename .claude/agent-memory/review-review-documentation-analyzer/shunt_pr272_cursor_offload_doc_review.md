PR #272's request-framing and large-image decode offloads add no config, endpoint, CLI, default, provider, model, or normal response-behavior change, and the cited #256 precedent accurately touched only `src/` and `benches/`. The useful review trap is error classification: new failures around pre-send CPU work may be mapped through an existing transport-error mapper and thereby contradict the ordered-failover specification's statement that Cursor adapter-owned errors return immediately. Fix commit `b73f31a` moved framing into `forward` and maps framing/image task failures through `own_error` (`failure: None`), restoring the spec; in `proxy/failover.rs`, only `UpstreamStatus` advance statuses and `BeforeHeaders` advance, while `None` returns immediately.

**Why:** The initial implementation constructed `cursor request framing: ...` before any upstream request but routed it through `map_client_error`, which marks all such errors `AdapterFailure::BeforeHeaders`; ordered failover advanced those failures, while the spec grouped Cursor adapter-owned errors with local errors that do not advance. After the fix, both framing and image-decode task failures are local 500s. The public API breaks in exactly **two** ways, both already enumerated in the PR's `BREAKING CHANGE` footer: `AgentRunParams<'a>` borrowed fields became owned, and `CursorAgentClient::open_turn` now takes `Vec<Bytes>`. A first-pass review of this PR also claimed `AgentImage` lost `Clone` — that is **false**: `Clone` appears nowhere in `agent.rs` on `origin/main` or on this branch, so `AgentImage` never had it. This PR only *adds* `#[derive(Debug, PartialEq, Eq)]` to that type, which is purely additive.

**How to apply:** On future Cursor internal/offload refactors, trace every newly possible local error through `AdapterError.failure` and compare it to `docs/upstreams-failover.md` §6, even when the PR is otherwise described as performance-only. Exact internal error strings do not need user docs unless an existing contract enumerates them. Re-check PR release notes after review fixes because later commits can change the final public signature. When claiming a trait impl was *removed*, diff the type against the merge base before writing it up — an added `#[derive(...)]` line reads like a replaced one in a one-sided diff view, and a fabricated break in a `BREAKING CHANGE` footer is worse than a missing one.
