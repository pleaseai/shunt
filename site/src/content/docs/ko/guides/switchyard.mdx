shunt의 [스테이지 라우터](/ko/guides/stage-router/)는 자체 스코어링을 만들지
않았습니다. [NVIDIA-NeMo/Switchyard][sy]의 라우팅 라이브러리
[`switchyard-libsy`][libsy]에 의존합니다 — "각 LLM 호출을 성공 가능성이 있는 가장
저렴한 모델로 보낸다"를 목표로 내건 프로젝트입니다.

이 문서는 통합 기록입니다. shunt가 Switchyard의 어느 부분을 쓰고 어느 부분을
의도적으로 쓰지 않는지, 공개된 수치가 실제로 무엇을 측정한 것인지, 알고리즘이 한
턴을 어떻게 판정하는지를 다룹니다. 기능을 켜는 방법만 필요하다면
[스테이지 라우터 가이드](/ko/guides/stage-router/)가 더 짧습니다.

[libsy]: https://crates.io/crates/switchyard-libsy
[sy]: https://github.com/NVIDIA-NeMo/Switchyard

## shunt가 가져온 것

Switchyard는 게이트웨이 한 벌을 제공합니다. 프록시 서버, 프로바이더 중립 프로토콜,
요청/응답 번역, LLM 판정자 분류기, 에스컬레이션, 서브에이전트 라우팅까지. shunt는
이미 게이트웨이이므로 스코어러 하나만 가져오고 나머지는 두고 옵니다.

| Switchyard 구성 요소 | shunt에서 |
| :-- | :-- |
| `switchyard-libsy` 스테이지 스코어러 | **사용** — `0.2` 라인에 고정 |
| `switchyard-protocol` | libsy의 의존성으로 딸려옴. shunt는 `Request`를 만들지 않음 |
| `switchyard-translation` | **미사용** — shunt의 `src/model/responses_request.rs`와 정면으로 중복 |
| `switchyard-server` | **미사용** — shunt가 곧 서버 |
| LLM 분류기 / 판정자 | **미사용** — [아래](#핫-패스에-llm-판정자를-두지-않는다) 참고 |
| 에스컬레이션 라우팅(턴 중간) | **미사용** — shunt의 post-2xx 무재생 규칙과 충돌 |
| 핸드오프 노트, 어드바이저 게이트, 서브에이전트 라우팅 | **미사용** |

결합점은 함수 호출 하나가 전부입니다. shunt는 파싱된 Anthropic Messages 본문에서
libsy의 `ToolSignals` 구조체를 직접 채우고 `pick_tier`를 호출합니다. 그 구조체의
모든 필드가 `pub`이라 사이에 번역 계층이 들어가지 않습니다.

버전은 `0.2`로 고정하고 자동 업그레이드에서 제외합니다. `0.2.0`이 유일한 공개
릴리스이고 업스트림 `main`은 이미 갈라졌습니다 — 그쪽 `ToolSignals`에는 필드가 네
개 더 있습니다. API를 확인할 때는 GitHub이 아니라 레지스트리 소스를 읽으세요.

- 이 표에는 지연 시간이나 요청당 라우팅 오버헤드 수치가 함께 공개되지 않았습니다.
  업스트림은 그 질문을 자체 soak 테스트 문서로 넘깁니다.

### shunt로 넘어오는 것과 넘어오지 않는 것

스코어러는 같은 코드입니다. 그 주변은 전부 shunt의 것이므로, 위 표는 shunt 자신의
결과가 아니라 *접근 방식이* 값을 한다는 증거로 읽으세요.

| | 업스트림 벤치마크 | shunt |
| :-- | :-- | :-- |
| 스코어링 코어 | `switchyard-libsy` | 같은 크레이트, 같은 상수 |
| 신호 추출 | 업스트림의 프로바이더 중립 추출기 | shunt 자체 구현, Anthropic Messages 블록에서 |
| `tests_passed` / `compacted` | 스코어러가 사용 가능 | 항상 `false` — 채워지지 않음 |
| 모호한 턴의 판정자 | 선택적으로 사용 가능 | 없음. 피커 기본값으로 fall-open |
| 턴 간 티어 안정성 | 턴마다 독립 채점 | 비대칭 히스테리시스를 건 세션 고정 |
| 워크로드 | Terminal-Bench 2.1 태스크 | Claude Code 세션 |

이 중 둘은 반대 방향으로 작용합니다. shunt는 `tests_passed`와 `compacted`를 채우지
않으므로 libsy의 하드 강등 지름길과 컴팩션 오버라이드가 빠집니다 — 벤치마크보다
엄격히 신호가 적습니다. 반대로 shunt의 히스테리시스는 벤치마크 하니스가 결코 치르지
않는 비용, 즉 Claude Code 세션에서 턴마다 티어를 뒤집는 대가가 비싸기 때문에
존재합니다([아래](#shunt가-더하는-것) 참고).

## 라우팅 알고리즘

### 1. 신호

shunt는 요청의 `messages` 배열을 두 번 훑습니다. 먼저 어시스턴트 메시지에서
`tool_use.id → tool_use.name`을 만들고, 다음으로 사용자 메시지의 `tool_result`
블록을 훑으며 각각을 `tool_use_id`로 원래 호출에 다시 잇습니다. `tool_result` 블록은
도구 이름을 담지 않으므로, 이 조인이 추출기 전체가 딛고 선 단 하나의 지점입니다.

읽는 필드는 `tool_use.name`과 `tool_result.is_error` 둘뿐입니다. 시스템 프롬프트도,
사용자 텍스트도, 도구 인자도 읽지 않습니다.

Claude Code는 실패를 등급 없는 불리언 하나로만 보고하므로, shunt가 직접 libsy의
`0.0 / 0.3 / 0.7 / 1.0` 심각도 척도에 매핑합니다.

| 조건 | `severity` |
| :-- | :-- |
| 윈도 안에 실패한 결과 없음 | `0.0` |
| 윈도 안에 실패한 결과 있음 | `0.7` (hard) |
| `Task` 실패 — 위임된 서브에이전트 실행 전체가 무너짐 | `1.0` (critical) |
| 마지막 두 완료 결과가 모두 실패 — 회복 중이 아님 | `1.0` (critical) |

도구 이름은 [어휘](/ko/guides/stage-router/#도구-어휘)에 따라 `Observe`, `Mutate`,
`Plan`, 미분류로 나뉩니다. `Bash`는 의도적으로 미분류입니다 — `git status`,
`rm -rf`, `cargo test`를 가르는 것은 `input.command`를 읽는 것뿐이고, 그것이 바로 이
설계가 피하려는 취약한 추론입니다.

완료된 도구 호출이 하나도 없으면 추출은 아무것도 반환하지 않고 턴은 피커 기본값을
받습니다. 빈 대화는 "efficient"로 채점되지 않습니다.

### 2. 차원

신호는 두 축으로 투영됩니다 — 무언가 *잘못되었는가*, 그리고 에이전트가 *생산하고
있는가*.

| 차원 | 의미 | 미는 방향 |
| :-- | :-- | :-- |
| `severity` | 윈도 내 최대 오류 심각도, `[0, 1]` | Capable |
| `spinning` | 읽기·계획·쓰기·편집이 전무한 깊은 턴 — 순수한 헛돎 | Capable |
| `exploring` | 읽거나 계획하지만 쓰지도 편집하지도 않는 깊은 턴 | Capable |
| `production_intensity` | 최근 도구 연산 중 쓰기+편집의 비율 | Efficient |

`spinning`과 `exploring`은 둘 다 `turn_depth >= 8`을 요구합니다. 쓰기가 없는 초반
턴은 정체가 아니라 평범한 탐색입니다. 둘은 같은 "생산하지 않음" 상태를 조사 활동
유무로 분할하므로 최대 하나만 발동하고, 생산 축이 이중으로 계산되는 일은 없습니다.

### 3. 점수

최대치에 도달한 차원 하나가 `0.10`의 신호 단위 하나를 기여하며, `severity`는 hard
상한인 `0.7`로 정규화되어 같은 가중치에 놓입니다.

```
raw   = 0.10 × (severity / 0.7 + spinning + exploring − production_intensity)
score = tanh(5.0 × raw)          // 부호: + capable, − efficient
confidence = |score|
```

게인 `5.0`이 범위를 쓸 만하게 만듭니다. 이것이 없으면 신뢰도는 `±0.20` 부근에서
포화해 어떤 유의미한 문턱에도 닿지 못합니다.

설계는 **상호 보강적**입니다. 어떤 단일 축도 혼자서 판정을 확정할 수 없습니다.

| 합치하는 신호 | `raw` | `confidence` | `0.5` 기본값 통과? |
| :-- | --: | --: | :-- |
| 하나 포화 | `0.10` | `tanh(0.5) ≈ 0.46` | 아니오 |
| 둘이 상호 보강 | `0.20` | `tanh(1.0) ≈ 0.76` | 예 |

`0.5` 기본값은 여기서 나옵니다. 잘못된 신호 하나만으로는 턴을 움직이기에 부족하고,
합치하는 신호 둘이면 충분합니다.

### 4. 판정

`pick_tier`는 규칙 넷을 순서대로 돌리고, 먼저 발동한 것이 이깁니다.

1. **하드 승격** → capable. 심각도 critical 또는 컴팩션된 컨텍스트. 스코어러를
   건너뛰고 `confidence: 1.0`을 보고합니다.
2. **하드 강등** → efficient. 테스트가 통과했고, 코드가 최근 쓰였으며, 오류가 없음.
   스코어러를 건너뛰고 **신뢰도를 아예 보고하지 않습니다**.
3. **스코어러.** `confidence >= confidence_threshold`이면 부호를 따릅니다.
4. **Fall-open.** 문턱 미달이면 libsy가 `ConsultClassifier`를 반환합니다. shunt는
   분류기를 돌리지 않으므로 턴은 피커의 기본 티어에 안착합니다.

승격이 강등보다 먼저 검사되므로, 때마침 테스트도 통과한 턴에서 critical 오류가 여전히
이깁니다.

오늘의 shunt에서 규칙 2는 발동할 수 없습니다. 추출기가 `tests_passed`를 무조건
`false`로 두기 때문인데, 이를 판정하려면 Claude Code의 `Bash` 결과 *텍스트*를 패턴
매칭해야 하고 그것을 틀리면 정확히 아픈 방향으로 비쌉니다. 규칙 1의 컴팩션 절반도
같은 이유로 잠들어 있습니다 — 아직 고정된 컴팩션 마커가 없습니다. critical 심각도는
위 심각도 표의 두 경로를 통해 여전히 규칙 1을 발동시킵니다.

### 5. 히스테리시스

여기까지는 한 턴을 고립적으로 판정합니다. 그다음 shunt는 그 판정이 세션의 고정된
티어를 움직이도록 허용하기 전에 자체 게이트를 겁니다.

| 방향 | 요구 조건 |
| :-- | :-- |
| Efficient → Capable | 스코어러가 실제로 내린 판정이 `confidence_threshold`(0.5) 통과 |
| Capable → Efficient | 스코어러가 실제로 내린 판정, **그리고** `min_dwell_turns` 경과, **그리고** `deescalate_threshold`(0.75) |

Fall-open, 모호한 턴, 도구 활동이 없는 턴은 증거가 아니라 피커의 기본값이며, 어느
방향으로도 핀을 움직일 수 없습니다.

`tests_passed` 지름길은 *신뢰도* 게이트에서는 면제되지만 dwell에서는 아닙니다 —
신뢰도를 아예 보고하지 않으므로, 맨 `confidence >= threshold` 검사를 걸면 싸게 내려갈
가장 강한 근거가 유일하게 발동 불가능한 근거가 되어버립니다. 이 면제는 위에 적은
이유로 오늘은 비활성이며, 나중에 신호를 채우는 일이 추출기만 고치면 되도록 남겨둔
것입니다.

## shunt가 더하는 것

Switchyard는 프로바이더 중립이라 티어 전환의 대가를 가격 매길 필요가 없습니다.
shunt는 Claude Code 게이트웨이이므로 그래야 하고, 여기 나열된 것 대부분이 그 차이에서
나옵니다.

### Claude Code의 실제 도구 어휘

스코어러가 알고 싶은 것은 어떤 호출이 관찰했는지, 변경했는지, 계획했는지입니다.
프로바이더 중립 라우터는 그것을 추론해야 하지만 shunt는 이름을 압니다. `Read`,
`Glob`, `Grep`, `Edit`, `Write`, `TodoWrite`, `Task`, `ExitPlanMode`가 직접
매칭되고, *실패한* `Task`는 명령 하나가 아니라 위임된 서브에이전트 실행 전체가
무너진 것이므로 hard가 아니라 critical로 채점됩니다.

### 전환이 공짜가 아니기에, 비대칭 히스테리시스

긴 Claude Code 세션에서 티어 전환은 구체적으로 세 가지를 치릅니다.

- **프롬프트 캐싱은 모델별로 키가 걸립니다** — 전환하면 따뜻한 프리픽스를 잃고 새
  티어에서 캐시 쓰기를 전액 지불합니다.
- **Codex 컨티뉴에이션**은 모델을 시그니처에 해싱하므로, 전환은 전체 재전송을
  강제하고 shunt가 방금 벌어놓은 업로드 절감을 되돌려줍니다.
- **프로바이더를 넘는 전환**은 세션의 풀링된 커넥션과 끈적한 계정 슬롯까지
  버립니다.

턴마다 독립적으로 채점하면 긴 세션은 라우팅하지 않을 때보다 *더* 비쌀 수 있습니다.
두 방향이 불평등한 이유이자, 히스테리시스가 shunt 통합의 곁가지가 아니라 핵심인
이유입니다.

### 세션 id를 흘리지 않는 세션 고정

판정은 `(광고된 모델 id, 세션 id)` 단위로 고정되며 키는 SHA-256 프리픽스입니다 —
세션 id는 해싱되고 저장되지 않습니다. 저장소는 4096 세션에서 상한에 걸리고, 삽입
경로에서 축출하며 백그라운드 태스크가 없고, 아무것도 영속하지 않습니다.

핀은 자신이 만들어진 라우터 테이블의 지문도 기억하므로, 핫 리로드를 가로질러 라우터
하나를 편집하면 그 라우터의 핀만 버려집니다. 그 지문은 설정 구조체를 점 접근이 아니라
구조 분해로 읽으므로, 나중에 키가 추가되면 낡은 핀이 조용히 살아남는 대신 컴파일이
깨집니다.

### 핫 패스에 LLM 판정자를 두지 않는다

신호가 불확실하면 libsy는 `PickOutcome::ConsultClassifier { default_tier }`를
반환합니다. shunt는 그것을 답으로 취급하고 `default_tier`를 씁니다. 판정자를 거절하는
것은 API와 싸우는 게 아니라, API가 문서화한 fall-open 경로 *그 자체* 입니다.

얻는 것은 두 번째 모델 호출 없음, 두 번째 자격 증명 없음, 그리고 라우터가 가장
불확실한 바로 그 턴에서 지연이 늘지 않음입니다. 치르는 것은 그런 턴에서 판정자가
회복해줬을 정확도이며, 이는 업스트림의 분류기 보조 구성이 측정한 것의 실질적인
일부입니다.

### 라우팅된 타깃은 평범한 모델 id

라우터의 출력은 공개 모델 id이므로 shunt의 일반 라우팅 사다리에 다시 진입해
페일오버 체인, 계정 풀, 어댑터 선택, `effort`, `service_tier`를 공짜로 물려받고,
추가 코드 없이 `/v1/models` 디스커버리에 나타납니다. 타깃이 또 라우터이면 시작
오류이므로, 해석은 깊이 카운터가 아니라 **구조적으로** 한 홉입니다.

### 클라이언트는 여전히 자신이 요청한 id를 본다

티어는 `upstream_model`을 타고 업스트림으로만 갑니다. 응답은 요청된 id를 보고하므로
Claude Code의 `/model` 표시와 `--resume` 모델 복원이 그대로 동작합니다.

### 요청하지 않으면 비활성

`[models.stage_router]` 테이블이 없으면 라우터 분기는 기존 배포에 존재하지 않는 설정
필드에 대한 `Option` 검사 하나입니다. 라우팅 경로에서 달라지는 것은 없습니다.
