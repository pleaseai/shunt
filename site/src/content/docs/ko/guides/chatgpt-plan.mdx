---
title: ChatGPT 플랜 (Sign in with ChatGPT)
description: OpenAI의 "Sign in with ChatGPT" 토큰 공유 프리뷰를 통해 Claude Code 추론을 ChatGPT 플랜으로 라우팅하기 — 로그인, 여러 계정 풀링, 로그아웃, 프리뷰의 제한.
---

내장 **`chatgpt-plan`** 프로바이더는 OpenAI의 "Sign in with ChatGPT"(SIWC) 토큰 공유 프리뷰를 통해
**ChatGPT 플랜** 사용량을 소비합니다. 처음 로그인할 때 shunt가 스스로를 에이전트 클라이언트로 등록하고,
이후에는 API 키 대신 플랜 사용량용 액세스 토큰으로 공개 엔드포인트
`api.openai.com/v1/responses`를 호출합니다.

이 프로바이더는 **`kind = "responses"`** 이므로 [Codex](/ko/guides/codex/) 및 [xAI](/ko/guides/xai/)와
변환 경로를 공유합니다. 다만 **`codex` 프로바이더와는 별개**입니다:

| | `chatgpt-plan` | `codex` |
| :-- | :-- | :-- |
| 로그인 | `shunt login chatgpt-plan --name <account>` — 서드파티 도구를 위한 OpenAI 공식 프리뷰 | Codex CLI 로그인(`~/.codex/auth.json`) 재사용 |
| 백엔드 | `api.openai.com/v1/responses` | `chatgpt.com/backend-api` |
| 자격 증명 | `~/.shunt/accounts/chatgpt-plan/<name>.json`, 이름 있는 계정마다 파일 하나 | `~/.codex/auth.json` 또는 `~/.shunt/accounts/codex/` |
| 프리뷰 제한 | 있음 — 아래 "프리뷰 제한" 절 참고 | 없음 |

둘은 자격 증명이나 설정을 공유하지 않으므로 함께 구성해도 됩니다.

<Aside type="note" title="필요한 것">

OpenAI가 토큰 공유 프리뷰를 활성화한 ChatGPT 플랜, 브라우저, 그리고 `shunt.toml`의 라우트가
필요합니다. 자격이 있는지는 OpenAI가 결정합니다. 자격이 없는 계정은 모든 요청에서
`permission_error`를 받습니다(아래 "오류의 의미" 절 참고).

</Aside>

## 설정

### 1. 로그인

```bash
shunt login chatgpt-plan --name work
```

shunt가 인증 URL을 출력하고 브라우저를 엽니다. 플랜 사용량을 포함한 요청을 승인하세요. 브라우저가
shunt가 대기 중인 `http://127.0.0.1:1455/auth/callback`으로 리디렉션되면 명령이 스스로 끝납니다:

```text
ChatGPT plan account "work" signed in as you@example.com.
Scopes granted: openid profile email offline_access resource.invoke chatgpt.tokens.use.direct
```

무엇이든 저장하기 전에 shunt는 콜백의 state를 확인하고, 코드를 교환하며, OpenAI가 공개한 키로 ID
토큰을 검증합니다. 검증에 실패한 로그인은 자격 증명을 저장하지 않습니다.

같은 이름의 첫 로그인은 OpenAI에 클라이언트 ID(`oaiapp_…`)를 등록하고 계정과 함께 저장합니다. 같은
이름으로 다시 로그인하면 이를 재사용합니다. `--long-lived`, `--mode`, `--manual`은 거부됩니다. 플랜
토큰은 항상 갱신 가능하고, 콜백 붙여넣기는 언제나 쓸 수 있기 때문입니다(다음 절).
[`shunt login chatgpt-plan`](/ko/reference/cli/#shunt-login-chatgpt-plan)을 참고하세요.

### 2. 프로바이더와 라우트 추가

```toml
[providers.chatgpt-plan]
kind = "responses"
base_url = "https://api.openai.com/v1"   # shunt가 /responses를 붙임
auth = "chatgpt_plan_oauth"

[[routes]]
model = "gpt-6.1-sol"
provider = "chatgpt-plan"
```

사용할 모델 ID를 라우팅하세요. shunt는 계정의 모델 목록을 조회하지 않고 매핑한 ID를 그대로 제공합니다.
순서가 있는 `[[upstreams]]` 목록에서는 `provider = "chatgpt-plan"`이 세 개의 프로바이더 키를 채웁니다.

파일을 확인하고 게이트웨이를 시작합니다:

```bash
shunt check
shunt run
```

`shunt check`는 `kind`가 `responses`가 아니거나, `base_url`이 HTTPS가 아니거나, 호스트가
`api.openai.com`이 아닌 `chatgpt_plan_oauth` 프로바이더를 거부하며, `chatgpt-plan`이라는 이름의
프로바이더가 다른 `auth`를 쓰는 경우도 거부합니다. 문제의 키 이름을 알려 줍니다. shunt는 플랜 토큰을
다른 호스트로 보내지 않습니다.

## 원격 및 헤드리스 호스트

브라우저 콜백은 **로그인 명령을 실행한 머신의** `127.0.0.1:1455`로 갑니다. 브라우저가 다른 곳에 있다면
다음 중 하나를 쓰세요:

- **콜백 붙여넣기.** 아무 브라우저에서나 승인합니다. 마지막 리디렉션은 로드되지 않지만(정상입니다)
  주소 표시줄에는 `http://127.0.0.1:1455/auth/callback?code=…`로 시작하는 전체 URL이 남아 있습니다.
  이를 복사해 대기 중인 터미널에 붙여넣으세요. 앞뒤 공백이나 따옴표는 괜찮습니다. shunt는 코드를
  교환하기 전에 URL이 이번 로그인 시도의 것인지 확인합니다.
- **포트 포워딩.** SSH에서 `ssh -L 1455:127.0.0.1:1455 <host>`를 실행한 뒤 평소처럼 로그인합니다.
  그러면 브라우저의 콜백이 원격 호스트의 shunt에 도달합니다.

1455 포트가 이미 사용 중이면 shunt가 그렇게 알리고 붙여넣기 전용 모드로 계속합니다. 대기는 5분 뒤에
끝납니다.

## 여러 계정

각 계정을 고유한 이름으로 로그인합니다:

```bash
shunt login chatgpt-plan --name work
shunt login chatgpt-plan --name personal
```

각 계정은 `~/.shunt/accounts/chatgpt-plan/<name>.json`(`0600`, `0700` 디렉터리 안;
`$SHUNT_CHATGPT_PLAN_ACCOUNTS_DIR`로 디렉터리 변경)입니다. 두 이름이 같은 이메일을 가질 수 있으며,
각각 자기 레코드와 클라이언트 ID를 유지합니다. 추가 설정이 없으면 프로바이더는 디렉터리의 모든 계정을
사용합니다. 일부만 고르거나 하나를 우선하려면:

```toml
[[providers.chatgpt-plan.accounts]]
name = "work"

[[providers.chatgpt-plan.accounts]]
name = "personal"
priority = 200          # 선택: 낮을수록 우선 (기본값 100)
```

shunt는 세션(`x-claude-code-session-id`)을 한 계정에 고정하고, 그 외에는 순환합니다. 응답한 계정은
`x-shunt-account` 응답 헤더에 표시됩니다. 호스트 식별자(같은 디렉터리의 `.host-id`)는 한 번 만들어져
모든 로그인에 함께 전송되므로 그대로 두세요.

## 로그아웃

```bash
shunt logout chatgpt-plan --name work
```

shunt는 OpenAI의 폐기(revocation) 엔드포인트에서 계정의 refresh 토큰을 폐기한 뒤, 계정의 액세스,
refresh, ID 토큰을 지웁니다. **등록된 클라이언트 ID는 유지**하고 호스트 ID도 유지하므로, 다시
로그인하면 같은 등록을 재사용합니다.

| 결과 | 의미 |
| :-- | :-- |
| `… signed out; remote revocation confirmed.` | OpenAI가 200으로 응답했습니다. 세션이 폐기되었습니다. |
| `… signed out locally; remote revocation not confirmed — finish in ChatGPT settings.` | 네트워크가 실패했거나 몇 번 시도한 뒤에도 OpenAI가 5xx로 응답했습니다. 또는 로그아웃 도중 계정의 토큰이 바뀌어(게이트웨이가 갱신했거나 새 로그인이 저장됨) 현재 세션은 폐기되지 않았습니다. 이 머신의 토큰은 지워졌지만 OpenAI 쪽 세션은 아직 살아 있을 수 있습니다. ChatGPT 설정에서 직접 제거하세요. |
| `… is already signed out.` | 계정에 토큰이 없었습니다. 아무것도 전송하지 않았습니다. |

실행 중인 게이트웨이는 로그아웃된 계정을 로그인이 필요한 계정으로 취급합니다.
[`shunt logout chatgpt-plan`](/ko/reference/cli/#shunt-logout-chatgpt-plan)을 참고하세요.

## 요청 동작

- **갱신.** shunt는 액세스 토큰이 만료되기 직전에 갱신하며, OpenAI가 허용한 시점보다 일찍 갱신하지
  않고, 교체된 refresh 토큰을 저장합니다. 토큰을 직접 관리할 필요가 없습니다.
- **사용량 한도.** 계정이 플랜 사용량 한도를 알리면(HTTP 429이거나 출력 전의 스트림 내 실패) shunt는
  그 계정을 쿨다운시키고 같은 요청을 다른 계정으로 처리합니다. 모든 계정이 쿨다운 중이면 Claude Code는
  [chatgpt.com/settings/usage](https://chatgpt.com/settings/usage)를 가리키는 `rate_limit_error`를
  받습니다.
- **만료된 로그인.** `401`이면 shunt가 토큰을 한 번 갱신하고 재시도합니다. 갱신이 실패하면 계정은
  로그인이 필요한 상태로 표시되고, 정상 계정이 요청을 처리하는 동안 몇 분간 쉽니다.
  `shunt login chatgpt-plan --name <account>`를 다시 실행하세요.
- **자격 없음 또는 지원되지 않는 라우트.** `403`은 재시도나 로그인 안내 없이 `permission_error`로
  전달됩니다.
- **일시적 불가.** `503`은 자격 증명을 유지한 채 다음 계정으로 넘어갑니다. 모든 계정이 `503`으로
  응답하면 Claude Code는 `overloaded_error`를 받습니다.

## 프리뷰 제한

- **거부되는 파라미터.** 프리뷰는 `temperature`, `metadata`, `prompt_cache_retention`을 거부합니다.
  shunt는 이를 절대 보내지 않습니다. Claude Code가 비스트리밍 응답을 요청하더라도 항상
  `store: false`와 `stream: true`를 보내며, shunt가 완성된 메시지 하나로 돌려줍니다.
- **도구.** 일반 함수 도구는 동작합니다. 프리뷰가 거부하므로 이 프로바이더에서는 `tool_search` 설정과
  관계없이 네이티브 `tool_search`가 꺼져 있습니다. 호스티드 `web_search`는 그대로 통과합니다.
- **출력이 시작된 뒤의 한도.** 답변의 일부가 이미 Claude Code에 전달된 뒤 사용량 한도가 도착하면, 그
  턴은 다른 계정으로 옮길 수 없습니다. 스트림이 `rate_limit_error`로 끝나고 계정은 쿨다운됩니다. 다음
  요청은 다른 계정을 사용합니다.
- **에스컬레이션과 advisor 호출.** 이 호출들은 idle 제한 아래에서 실행되며, shunt는 이들에 대해
  출력 전 검사를 건너뜁니다. 이런 호출에서 스트림 내 사용량 한도가 도착하면 호출이 해당 오류로
  끝나고 다른 계정으로 순환하지 않습니다. 계정은 그래도 쿨다운되므로 다음 호출은 다른 계정을 씁니다.
  HTTP 429로 오는 사용량 한도는 평소처럼 순환합니다.
  [에스컬레이션](/ko/guides/escalation/)과 [advisor 게이트](/ko/guides/advisor/)를 참고하세요.
- **잘린 응답.** `max_tokens`로 잘린 응답은 현재 `max_tokens`가 아니라 `end_turn`으로 끝납니다. 모든
  Responses 프로바이더에 해당하며
  [이슈 #868](https://github.com/pleaseai/shunt/issues/868)에서 추적 중입니다.
- **모델.** shunt는 라우팅한 ID를 그대로 전달합니다. 플랜이 어떤 모델을 쓸 수 있는지는 OpenAI가
  결정하며, 계정이 쓸 수 없는 모델은 업스트림 오류로 돌아옵니다.

## 오류의 의미

| 업스트림 코드 | 상태 | Claude Code가 보는 값 | 의미와 대응 |
| :-- | :-- | :-- | :-- |
| `subscription_sharing_usage_limit_exceeded` | 429 | `rate_limit_error` | 계정이 플랜 사용량을 다 썼습니다. shunt가 다른 계정을 시도하며, 남은 계정이 없으면 기다리거나 [사용량 설정](https://chatgpt.com/settings/usage)을 확인하세요. |
| `subscription_sharing_usage_unavailable` | 503 | `overloaded_error` | OpenAI가 지금은 계정의 사용량을 읽을 수 없습니다. 자격 증명은 유지되며, 잠시 후 다시 시도하세요. |
| `subscription_sharing_user_unavailable` | 503 | `overloaded_error` | OpenAI가 지금은 이 사용자를 처리할 수 없습니다. 자격 증명은 유지되며, 잠시 후 다시 시도하세요. |
| `subscription_sharing_unsupported_capability` | 400 | `invalid_request_error` | 요청이 프리뷰가 지원하지 않는 것을 사용했습니다. 메시지 끝에 `(parameter: <name>)`(예: `tools`)이 붙습니다. |
| `subscription_sharing_user_not_eligible` | 403 | `permission_error` | 이 ChatGPT 사용자는 토큰 공유 자격이 없습니다. 재시도하지 않습니다. |
| `subscription_sharing_route_not_supported` | 403 | `permission_error` | 프리뷰가 이 계정에 이 라우트를 지원하지 않습니다. 재시도하지 않습니다. |
| `chatpass_v2_*`(예: `chatpass_v2_scope_not_authorized`) | 403 | `permission_error` | 토큰에 호출에 필요한 권한이 없습니다. 다시 로그인하고 플랜 사용량을 승인하세요. 재시도하지 않습니다. |
| `subscription_sharing_invalid_user` | 401 | `authentication_error` | 토큰이 거부되었습니다. shunt가 한 번 갱신하고 재시도하며, 그래도 실패하면 `shunt login chatgpt-plan --name <account>`를 실행하세요. |
| `{"detail": "Unsupported parameter: …"}` | 400 | `invalid_request_error` | 프리뷰가 거부하는 파라미터가 전달되었습니다. 이슈를 열어 주세요. shunt가 보내면 안 됩니다. |

같은 코드가 `200 OK` 응답 안의 스트림 내 실패로도 도착할 수 있으며, 같은 방식으로 매핑됩니다. 이 표에
없는 코드는 다른 프로바이더의 오류처럼 HTTP 상태로 매핑됩니다.

## 문제 해결

| 증상 | 원인 / 해결 |
| :-- | :-- |
| `plan usage was not granted … chatgpt.tokens.use.direct` | 플랜 사용량을 승인하지 않았습니다. 계정은 로그아웃 상태로 남지만 클라이언트 ID는 유지합니다. 로그인을 다시 실행하고 승인하세요. |
| `registration incomplete: the authorization did not issue a client id` | 첫 로그인의 콜백에 클라이언트 ID가 없었습니다. 저장된 것은 없으니 로그인을 다시 실행하세요. |
| `the authorization returned a different client id than this account's saved registration` | 저장된 계정 파일이 다른 클라이언트 ID로 등록되어 있습니다. 파일은 변경되지 않았습니다. 새 `--name`으로 로그인하거나 계정 파일을 지우고 다시 등록하세요. |
| `the ChatGPT sign-in failed validation` | ID 토큰이 검사(nonce, audience, 만료, 서명)에 실패했습니다. 저장된 것은 없습니다. 반복되면 호스트의 시계를 확인하세요. |
| `the pasted callback belongs to a different sign-in attempt` | 이전 시도의 URL을 붙여넣었습니다. 현재 시도의 브라우저 탭 URL을 붙여넣으세요. |
| 오류 메시지의 `run shunt login chatgpt-plan --name <account>` | 계정이 로그아웃 상태이거나 갱신에 실패했습니다. 다시 로그인하세요. |

더 많은 내용은 [문제 해결](/ko/reference/troubleshooting/) 레퍼런스를 참고하세요.
