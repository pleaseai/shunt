---
title: 문제 해결
description: 흔한 shunt 오류와 해결 방법.
---

| 증상 | 원인 / 해결 |
| :-- | :-- |
| `ChatGPT auth not found; run codex login` | shunt가 `~/.codex/auth.json`을 읽을 수 없습니다. `codex login`을 실행하세요. |
| 매핑된 모델에서 `authentication_error` | 만료/부재한 프로바이더 자격 증명 — `codex login`을 다시 실행하거나 `OPENAI_API_KEY`를 export하세요. shunt는 백엔드의 실제 `detail` 메시지를 노출합니다. |
| <!-- shunt-contract: gemini-code-assist strict-terminal malformed-fails non-idempotent-preheader tool-result-roundtrip no-writeback ai-studio-web-excluded --> Code Assist가 스트림을 닫을 때 Gemini가 완료 대신 실패함 | Gemini 성공 응답에는 명시적인 provider finish와 정상적인 transport closure가 모두 필요합니다. 해당 finish가 없는 EOF 또는 `[DONE]`, 유효하지 않은 UTF-8, malformed JSON 또는 미지원 필드, 초과 크기 데이터, 다중 candidate, terminal 이후의 데이터, truncated response는 명시적으로 실패 처리됩니다. Streaming 및 unary 모드는 동일한 terminal 및 provider-error 의미를 적용하며, embedded provider error를 가짜 성공으로 변환하지 않습니다. |
| Gemini tool history가 dispatch 전에 거부됨 | 클라이언트에 노출되는 `tool_use` ID는 진정한 Code Assist 호출 페어링 및 Gemini 3의 `thoughtSignature`를 보존합니다. 일치하는 ID를 `tool_result`로 반환하세요. 외래, 잘못된 형식, 중복 또는 고아 메타데이터와 필수 서명이 누락된 메타데이터는 복구 없이 거부됩니다. 유효한 결과는 다음 요청의 `functionResponse`가 됩니다. shunt는 이 메타데이터를 영구 저장하거나 다시 쓰지 않습니다. |
| Gemini의 transient status가 동일한 upstream으로 재시도되지 않음 | Gemini generation은 non-idempotent입니다. 응답 헤더 이전에 발생한 것으로 확인된 일시적 연결 또는 타임아웃 오류만 동일한 선택된 토큰, 프로젝트 및 페이로드로 재시도될 수 있습니다. 반환된 상태 코드 및 모든 본문 시점의 실패는 동일한 업스트림으로 재시도하지 않고 즉시 노출됩니다. |
| `400 … model is not supported when using Codex with a ChatGPT account` | `-codex` 슬러그(또는 계정에 부여되지 않은 것)를 사용했습니다. [models.json](https://github.com/openai/codex/blob/main/codex-rs/models-manager/models.json)에서 부여된 슬러그(예: `gpt-5.6-sol`, `gpt-5.5`)를 사용하거나 `upstream_model`을 설정하세요. |
| `/model`이 모델을 나열하지 않음 | `gpt-*` id에는 `ANTHROPIC_CUSTOM_MODEL_OPTION`을 사용하세요; [디스커버리](/ko/guides/model-discovery/)는 `claude`/`anthropic` 프리픽스 id만 노출합니다. |
| `opus`가 Opus 4.7을 선택하거나 `sonnet`이 Sonnet 4.6을 선택함 | Claude Code의 내장 별칭 표는 게이트웨이 세션에서 해당 티어로 고정합니다. `ANTHROPIC_DEFAULT_OPUS_MODEL=claude-opus-5`로 클라이언트 측 티어를 고정하거나 shunt에서 id를 다시 매핑하세요. [모델 별칭](/ko/guides/model-aliases/#별칭-해석)을 참고하세요. |
| Opus/Fable의 컨텍스트 윈도우가 200K로 표시됨 | Claude Code는 base URL이 `api.anthropic.com`일 때만 모델의 기본 1M 윈도우를 신뢰합니다. `opus[1m]` / `fable[1m]`을 선택하세요. [모델 별칭](/ko/guides/model-aliases/#1m-컨텍스트가-자동으로-적용되지-않음)을 참고하세요. |
| `/model`에서 Fable이 없거나 `claude-fable-5`가 Opus로 폴백함 | 단순 `ANTHROPIC_BASE_URL` 뒤에서는 Fable이 필터링됩니다. `ANTHROPIC_DEFAULT_FABLE_MODEL=claude-fable-5`를 설정하거나 [게이트웨이 로그인](/ko/guides/gateway-login/)을 사용하세요. [모델 별칭](/ko/guides/model-aliases/#선택기에서-fable이-사라짐)을 참고하세요. |
| 디스커버리가 절대 발동하지 않음 | 게이트웨이 자격 증명(`ANTHROPIC_AUTH_TOKEN`, API 키, 또는 `apiKeyHelper`)과 `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`로 게이팅됩니다. `claude --debug` → `[gatewayDiscovery]` 줄로 디버그하세요. |
| `config check failed` | `shunt check`를 실행하여 정확한 이유(bind 주소, 라우트의 알 수 없는 프로바이더, 잘못된 어댑터/인증)를 확인하세요. |
| Claude Code가 로그인을 요청함 | shunt가 매핑되지 않은 모델에 대해 전달할 수 있는 Anthropic 자격 증명(`ANTHROPIC_AUTH_TOKEN` / 로그인)을 설정하세요. base URL만으로는 자격 증명이 아닙니다. |
| 매핑된 모델에서 effort가 `medium`에 고정됨 | `CLAUDE_CODE_ALWAYS_ENABLE_EFFORT=1`을 설정하세요 — [노력 & 컨텍스트](/ko/guides/effort-and-context/#추론-노력)를 참고하세요. |
| 매핑된 모델에서 `400 Invalid schema for function '…': '…' is not a 'regex'` | OpenAI 백엔드는 도구 스키마의 모든 `pattern`을 Python `re`로 컴파일하므로 JavaScript 전용 정규식(`\p{Cc}`, `(?<name>…)`, `\u{…}`)을 거부합니다. Claude Code의 `Artifact` 도구가 그런 패턴을 포함합니다. shunt는 전달하는 스키마에서 이런 패턴을 제거합니다. strict 모드 밖에서 `pattern`은 권고 사항이라 힌트만 사라지지만, `description`이 그 제약을 항상 다시 적어 주지는 않습니다. 여전히 보인다면 업데이트하세요. |
| 매핑된 모델에서 도구 호출이 모든 선택적 매개변수가 채워진 채로 도착함 | 백엔드는 명시적 `strict`가 없는 function 도구를 strict 모드 쪽으로 정규화하며, 그 모드에서는 닫힌 매개변수 객체(`additionalProperties:false`)가 모든 속성을 필수처럼 다뤄 호출자가 설정하지 않은 값까지 모델이 채워 넣습니다. shunt는 전달하는 function 도구와 `tool_search_output` 안에 재생되는 스펙에 `strict:false`를 고정해 선택적 속성을 선택적으로 유지합니다; xAI/Grok 라우트에서는 검증되지 않아 필드를 보내지 않고, 네이티브 `tool_search`는 스키마에 선택적 속성이 없어 생략합니다. 여전히 보인다면 업데이트하세요. |
| 매핑된 모델에서 도구 검색이 비활성 상태(매 턴 모든 도구 스키마가 전송됨) | `ENABLE_TOOL_SEARCH=true`를 설정하세요. Claude Code는 퍼스트파티가 아닌 base URL 뒤에서 낙관적 도구 검색을 자동으로 비활성화합니다. shunt는 `tool_reference` 블록을 전달하며 미뤄 둔 스키마를 필요할 때 드러냅니다 — [ChatGPT / Codex → 도구 검색](/ko/guides/codex/#도구-검색)을 참고하세요. |
| `400 Deferred custom tools are only supported on Anthropic models… Received stealth/ox-alpha`(또는 다른 비 Claude 슬러그) | Claude Code가 Anthropic이 아닌 Messages 모델에 `defer_loading` / `tool_search_tool_*`를 보냈습니다. shunt는 `claude*` / `anthropic/*`가 아닌 업스트림 id에서 해당 필드를 제거한 뒤 전달합니다. OpenRouter의 Anthropic 슬러그는 프로토콜을 유지합니다. |
| 도구 검색은 동작하지만 컨텍스트를 회수하지 못함(여전히 텍스트 shim의 캐시 무효화 비용을 지불 중) | 네이티브 `tool_search`는 기본값("auto")에서 이미 지원이 검증된 호스트 — ChatGPT/Codex 백엔드와 `api.openai.com` — 에서만 적용되며, 계열/모델 게이트(스톡 OpenAI/ChatGPT-Codex 계열, gpt-5.4 이상 모델)도 함께 통과해야 합니다. 커스텀 OpenAI 호환 엔드포인트(LiteLLM, vLLM, OpenRouter, 자체 호스팅)는 자동으로 켜지지 **않으므로**, 프로토콜 지원을 확인한 뒤 `tool_search = true`를 설정하세요. 알려진 호스트에서 네이티브를 기대했는데 여전히 shim을 쓰고 있다면 `tool_search = false`를 설정하지 않았는지 확인하세요 — [ChatGPT / Codex → 도구 검색 → 네이티브 프로토콜](/ko/guides/codex/#네이티브-프로토콜)을 참고하세요. |
| 매핑된 모델에서 컨텍스트 길이 오류 후 세션이 멈춤 | shunt는 업스트림 오버플로 오류를 `prompt is too long …`으로 다시 써서 Claude Code가 자동 압축하고 재시도하도록 합니다 — [컨텍스트 오버플로 복구](/ko/guides/effort-and-context/#컨텍스트-오버플로-복구)를 참고하세요. 몇 턴마다 반복되면 `CLAUDE_CODE_MAX_CONTEXT_TOKENS`를 모델의 실제 윈도우로 낮추세요. |
| Cloudflare 뒤에서 스트림이 죽음(524) | [`sse_keepalive_seconds`](/ko/guides/shared-gateway/#sse-keepalive-ping)를 `0` 대신 기본값(30)으로 유지하세요. |
| 공유 게이트웨이에서 매핑된 모델에 401 | 누락/유효하지 않은 클라이언트 토큰 — `ANTHROPIC_AUTH_TOKEN=<token>`(`Authorization: Bearer`로 수락, 풀 전용 게이트웨이) 또는 `ANTHROPIC_CUSTOM_HEADERS="x-shunt-token: <token>"`(패스스루 모델이 섞여 있을 때 권장 — 각 호출자의 실제 자격 증명이 슬롯을 하나 확보하도록. `Authorization` / `x-api-key`에 실려 온 클라이언트 토큰은 전달되지 않고 그 슬롯에서 제거됩니다)을 설정하세요; [게이트웨이 공유](/ko/guides/shared-gateway/#인바운드-클라이언트-토큰)를 참고하세요. |
| Anthropic 어댑터 모델에서 429 | 게이트웨이 로그의 `rate_limit_kind`를 확인하세요. `quota`(`retry-after` / `anthropic-ratelimit-*` 헤더 동반)는 실제 rate limit입니다 — 백오프하거나 병렬 부하를 줄이세요. `client-shape-rejection`(OAuth 요청, 두 헤더 모두 없고 바디가 `"Error"`뿐)은 api.anthropic.com이 Claude Code처럼 보이지 않는 구독 OAuth 요청을 거부한 것입니다 — Claude Code가 아닌 클라이언트는 OAuth 토큰 대신 API 키를 사용해야 합니다. Claude Code의 auto-mode 권한 분류기는 업스트림이 확인하는 identity 블록을 빠뜨리는 유일한 first-party 요청이며, shunt가 그 요청에 한해 이를 복원하므로 auto mode가 "model temporarily unavailable"로 fail-closed 되지 않습니다. 나머지 요청은 모두 byte-for-byte 패스스루를 유지합니다. `no-ratelimit-headers`(비-OAuth 자격 증명)는 rate-limit 메타데이터 없는 프로바이더 429입니다 — `quota`처럼 취급하세요. |
| 공유 게이트웨이에서 `503 overloaded_error` | 게이트웨이가 인바운드 동시성 상한에 도달해 요청을 대기열에 넣지 않고 거부한 것입니다(바디 메시지 `too many requests are already in flight`, `Retry-After: 1` 동반). 업스트림 503이 아니라 shunt 자체의 admission control입니다 — 업스트림 503은 프로바이더의 메시지 그대로 릴레이됩니다. 지정된 시간 뒤에 재시도하거나, 병렬 부하를 줄이거나, [`max_concurrent_requests`](/ko/guides/shared-gateway/#인바운드-동시성-제한)를 올리고 재시작하세요(제한은 시작 시점에 고정됩니다). |

전체 게이트웨이 문제 해결 표는 [Connect Claude Code to an LLM gateway](https://code.claude.com/docs/en/llm-gateway-connect#troubleshoot-gateway-errors)를 참고하세요.
